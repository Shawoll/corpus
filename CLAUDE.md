# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Corpus is an interactive map of the human body, seen from the front and the back, (bones, joints, muscles, organs, blood vessels, nerves and "Where does it hurt?" regions). It is plain HTML, CSS, ES modules, JSON and SVG. There is no build step, no package manager, no dependencies and no external requests, and it deploys as-is to GitHub Pages from the repository root on `master`. Keep it that way: don't add a bundler, npm packages, CDN scripts or absolute paths. The one exception is **three.js** (MIT, r170), copied into `js/vendor/three/` for the 3D view and mapped by the import map in `index.html`; it loads only when the 3D view is opened. Don't add other libraries, and update it only by replacing those files with another pinned release.

`CONTRIBUTING.md` documents the project layout, the data shapes and the "add a layer" recipe in full. `data/CLAUDE.md` and `assets/svg/CLAUDE.md` hold the rules for editing data and drawings.

## Commands

```sh
python3 -m http.server 8000      # serve the folder; fetch() fails from file://
open http://localhost:8000/?debug # run the data check in the browser
node tools/check.mjs              # the same check headless (Node 22+, no packages); exits 1 on problems
python3 tools/realistic/build.py  # regenerate every *-realistic.svg (needs shapely; drawing tool only); rerun after editing any schematic SVG
~/.venvs/corpus/bin/python -I tools/model3d/build.py [layer…]  # rebuild assets/3d/*.glb + keys.json, and tools/realistic/outlines3d.json (numpy, meshoptimizer, shapely; needs the Z-Anatomy source, see tools/model3d/index_source.py); then rerun tools/realistic/build.py
~/.venvs/corpus/bin/python -I tools/model3d/coverage.py         # which structures have a 3D mesh
```

There are no tests, linter or build. The only automated check is the data check in `js/validate.js`: `check()` is pure and shared by `tools/check.mjs` (also run by `.github/workflows/check.yml` on every push) and by `?debug`, where `main.js` dynamically imports the module, logs a `[Corpus] data check` group to the console (a table of problems) and adds a badge to the page. Run it after any data or SVG change and get it to 0 issues. It runs once per biological sex setting (`checkAll()`, see below) and checks that every drawn shape has data, every reference and group resolves, paired and unpaired sides match, every structure that isn't `listOnly` is drawn in at least one view (and none that is `listOnly` is drawn), every region has a shape in its view, bone `count`s sum to 206, every bone (except ones with `noJoints`) has a joint, every joint connects something, every muscle has an origin or insertion, every nerve and vessel connects to something, every muscle has a nerve and a blood supply, and every organ has a blood supply. For the 3D model it reads each `.glb`'s JSON chunk (`glbNodes`) and checks that every mesh names a structure of its own layer for that sex, with the right side rules, that `assets/3d/keys.json` matches the files, and that every area of the skin (`skinFrom`) is a region of `regions.json`; coverage ("in 3D: 280/282") is reported, not required.

`window.corpus` exposes `{ graph, graphFor, map, store, zoom }` in the console for inspection, e.g. `corpus.graph.edges('femur:right')` (`graph` is the current biological sex's graph; `graphFor('male')` builds or returns another).

Data and SVG are fetched with `cache: 'no-cache'`, so a reload picks up edits.

## Architecture

**Boot (`js/main.js`)**: loads `data/manifest.json`, then every layer's JSON, its SVG text for each view, the link files and the regions in parallel. It builds one `Graph`, mounts all SVGs into the single `<svg id="map">`, and wires the store, router, panel, search, browse and controls. All DOM event handling for the panel lives here, delegated on data attributes the panel emits (see below).

**Graph (`js/graph.js`)** is the core model. The rest of the code works with graph keys, not raw JSON:
- A *key* is `id` for midline structures and `id:right` / `id:left` for `paired` ones (`parseKey`, `graph.k`, `keysFor`, `instances`). SVG shapes, highlights, routes and panel chips all use the same keys.
- A node's `type` comes from the structure's own `type`, else the data file's top-level `type` (`bone`, `muscle`, `organ`, `vessel`, `nerve`). Entries in a file's `joints` array become `type: 'joint'`. Panel and validation logic branch on `type`.
- Edges are stored in both directions in `adj`, with `dir` set to `out`, `in` or (for `articulates`) `both`. Joints add `articulates` edges with `via: <joint key>` and fill `jointMembers` / `memberJoints`.
- Links come from three sources: joints, `data/links.json`, and *field links*. A `linkTypes` entry in the manifest with a `field` turns that field on every structure into links: muscle `origin` / `insertion`, nerve `innervates`, artery `supplies`, and `branches`, `continues` and `drains` on nerves and vessels. To add a relationship, give the link type a `field` and put the field on the structures. No code change is needed.
- `resolvePair` applies the side rules (paired to paired same side, midline to both sides, explicit `:side` or link `side` narrows the match). `@group` refs expand to the whole group subtree.
- Unknown ids, groups and link types are collected in `graph.problems` instead of throwing. Only the data check shows them (`?debug`, `node tools/check.mjs`, CI), so a typo fails silently in normal use.
- The search index and its ranking weights are also built here.

**Views (front / back)**: `manifest.views` lists the views (`anterior`, then `posterior` with `"flip": true`), and each layer's and the regions' `svg` maps a view id to a file. A layer without a file for a view isn't shown there (its layer chip is disabled). The current view is `state.view`, saved in prefs and **not** part of the route: `onRoute()` switches view only when the route's structure, group or region isn't drawn in the current one (`viewFor()`, using `map.viewsOf()`). A flipped view is rendered with the mirror transform on `#world`; Mirror applies only to unflipped views. Whenever the flip changes, `zoom.mirrorX()` mirrors the viewBox so the same body part stays in frame.

**Drawing styles (schematic / realistic)**: `manifest.styles` lists the styles (the first is the default, drawn by each layer's `svg`). A layer's `styles` maps a style to per-view files with the same ids. Only the default drawings load at boot. `ensureStyle(style, view)` in `main.js` fetches the others the first time they're shown (current view first, then the others in the background; awaited at boot when the saved style isn't the default, and for every style under `?debug`), and `map.addStyle()` mounts each as a `<g class="layer" data-style=…>` right after its layer's default drawing. `render()` hides the other style's group with `.style-off` (kept hidden while probing), and shows the default drawings in a view whose style is still loading (`map.hasStyle()`). The current style is `state.style`, saved in prefs as `corpus:style` and not part of the route. The Drawings options in the cog (and the `D` key) are disabled in views where no layer has a drawing in that style. The data check compares each styled drawing's keys with its default drawing (`map.variants()`).

**Biological sex (none / female / male)**: `manifest.sexes` lists the settings (the first, "Not set", is neutral). Any object in the data can carry `"sex": "female" | "male"`. `js/sex.js`'s pure `forSex(raw, sex)` filters the raw data: sex-specific *entities* (structures, joints, groups, links, regions) exist only for their sex, so none exist when it is Not set; sex-specific *text* (issues, causes, members, functions, red flags, `sexNotes`) is hidden only for the other sex, and with Not set is shown with a "female" / "male" tag. References to dropped ids are stripped. `main.js` loads the raw data once and builds one `Graph` per sex on first use (`graphFor`); `setSex()` swaps `graph`, recreates the panel, re-points search (`search.setGraph`) and rebuilds Browse, then sets `state.sex` (saved in prefs as `corpus:sex`, not part of the route). Like `viewFor`, `onRoute()` switches sex when the route's structure, group or region exists only for another sex (`#/s/prostate`), and switching sex away from the page on show goes home. Sex-specific shapes carry `data-sex`; `map.render({ sex })` hides the others with `.sex-off` (kept hidden while probing). Controls: the Biological sex row in the cog and the `S` key (which cycles Not set → Female → Male). `checkAll()` in `validate.js` runs the data check once per sex and prefixes problems that occur only for some with `[female]`, `[male]` or `[not set]`.

**3D view (`js/model3d.js`)**: the third entry of `manifest.views` (`{ "id": "3d", "model": true }`) has no SVGs. Each layer's `model` names a `.glb` in `assets/3d/`, built by `tools/model3d/build.py` from the Z-Anatomy models (CC BY-SA 4.0, credited on screen and in `assets/3d/LICENSE.md`) through `tools/model3d/map.json` (Corpus id → source part names; `generated` lists ids the source lacks that `tools/model3d/generated.py` draws as simple stand-ins, tubes along courses anchored to source meshes, marked `extras.generated` and listed in `keys.json`, and the 3D view says so when one is selected; `missing` lists what stays 2D-only, such as every female organ). Every mesh carries its graph key in `extras.key` → `userData.key` (three.js strips `:` from node names) and `extras.sex` when it exists for one sex only. `main.js` loads the small `assets/3d/keys.json` at boot, so `layersIn('3d')` and `viewFor()` know what 3D shows, and imports `model3d.js` (and with it three.js) only when the view is first shown; then `ensureModelLayers()` starts each visible layer's `.glb` (and, in hurt mode, the skin) once, and each load redraws once when it lands; `modelNote()` picks the line at the top of the view (not in the model, a stand-in, loading progress). `createModel3d()` mirrors the map's interface: `render({ sel, rel, visible, active, sex })` tints selected and related meshes, fades context layers and draws the selection again on top without depth test (the 3D version of the outline overlay), `setHover`, `probe` (every hit under a point, hidden layers too), `frame(keys)` (in place of `zoom.reveal`; when the selection has no mesh, `renderMap` says so in `#model-status`), `home`, `zoomBy` and arrow-key `orbit`. Picking is a raycast on a tap (a press that moves under 6 px), and a miss tries rings of rays around the point (4 / 8 px, 7 / 14 px for touch) so thin nerves and vessels can be tapped; a drag turns the body (OrbitControls, with the up/down tilt limited). Colours come from the CSS tokens and are re-read on a theme change. In the cog, Display (2D / 3D, key M) switches between it and the last 2D view (`lastFlat`), and View (Front / Back, key B) picks the drawing in 2D but turns the model in 3D (`facing` / `setFacing`). The R / L labels follow the camera (`onTurn`), and Mirror and Drawings are disabled in 3D. Joint markers are meshes in `skeleton.glb` named with the joint keys (`extras.joint` = class), placed by the build where the member bones meet (`tools/model3d/joints.mjs` lists the bone pairs with `graph.js`'s side rules, `joints.py` finds the contact points); they are small (2.2 / 3.4 mm), shown only with Joints on and the skeleton in focus, and hidden by bone in front of them unless selected, related or hovered (then drawn on top, so a joint deep in a socket can still be found); a marker wins a tap only when it shows. "Where does it hurt?" works in 3D through `assets/3d/skin.glb` (`manifest.model3d.skin`): one skin mesh whose `_hurt` vertex attribute holds each vertex's place in the 2D frame (×16) and its area, both precomputed by `tools/model3d/skin.py` from a fit on the bones of `skeleton-anterior.svg` and from the region shapes of both region SVGs (front-facing skin takes the front areas). So `data/regions.json` and the region drawings stay the only source of the areas, and the skin must be rebuilt (`build.py skin`) after a region shape changes; `keys.json` lists the areas it covers (`skin`). Tapping the skin gives the area, the 2D point (so the 2D probe dot still fits) and the 3D point; "Under this spot" is every mesh along that line of sight. On an area's page the skin turns nearly clear except for the chosen area (per-vertex alpha). The source is a male body; the skin leaves the genitals out so it is the same for every sex setting. The frame matches the drawings: Y up, metres, facing +Z, the body's right at x < 0.

**Map (`js/map.js`)**: for each view, imports each SVG's children into `<g class="view" data-view=…>` → `<g class="layer" data-layer=…>` (in manifest order: first is drawn at the bottom). The inactive view gets `.off` (`display: none`), which also keeps it out of `probe()`. It then indexes every `[data-id]` element by key and clones each `.b` path as an invisible wider `.hit` path for tapping. `render()` toggles `is-sel` / `is-rel` classes, view and layer `off` / `active` / `context` classes, the mirror transform on `#world`, and outline overlays (only for the shown view). `probe()` uses `elementsFromPoint` with a `.probing` class to list everything under a tap across all layers, including hidden ones (the "Under this spot" list in hurt mode).

**State and routing**: `js/state.js` is a minimal store. Subscribers compare fields **by reference**, so always pass a new object (e.g. `new Set(prev.visible)`) and never mutate state in place, or the panel won't re-render. `js/router.js` handles hash routes: `#/s/<id>[/<side>][?m=<member>]`, `#/g/<group>`, `#/hurt`, `#/r/<region>[/<side>]`. Navigation is always `Router.go()` → `hashchange` → `onRoute()` → `store.set()` → render.

**Panel (`js/panel.js`)**: renders the current route to an HTML string. Every data value must go through `esc()`. Interactivity is declared with attributes that `main.js` handles: `data-nav` (route path), `data-keys` / `data-rkeys` (highlight on hover or focus), `data-expand` (open a collapsed range chip), `data-layer-on` (show a hidden layer) and `data-back` (return to the region). Runs of three or more numbered siblings collapse into one range chip using the structure's `ordinal` and the group's `rangeLabel` / `rangePrefix`. Link sections follow the `order` list in `linksSection` (a new link type not in it sorts last), and flow types in `UPSTREAM_FIRST` show the incoming side first. A link `note` shared by a whole section goes in its title; when notes differ (the kidney drains urine to the bladder and blood to the renal vein) each note labels its own chips. Nerve and vessel facts come from `kind`, `roots`, `carries` and `pulse`. `REGION_GROUPS` at the top hard-codes the order and grouping of the "Where does it hurt?" list, so **a new region must also be added there** or it won't appear in that list.

**Zoom (`js/zoom.js`)**: pans and zooms by animating the SVG `viewBox` rather than with CSS transforms. `reveal(bbox)` frames a selection.

**Styling**: `css/base.css` holds design tokens, typography and the light and dark themes. Dark tokens are defined twice: under `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` and under `:root[data-theme="dark"]`. Change both together. `css/app.css` holds layout and all map styling, keyed on SVG classes and `[data-layer=…]`. The theme toggle sets `data-theme` on `<html>`. Preferences (theme, joints, mirror, view) are stored in `localStorage` under keys prefixed `corpus:`.

## Conventions

- Anatomical orientation: the front figure faces the viewer, so the **body's right is on the viewer's left (x < 240)**. "Mirror" and the back view only flip the rendered view (`matrix(-1 0 0 1 480 0)` on `#world`). Data and **all** drawings, the posterior ones included, use this frame (see `assets/svg/CLAUDE.md`).
- Health content stays general and conservative, and every health page shows the disclaimer from `data/regions.json`. Urgency values are `self-care`, `doctor` and `urgent`.
- Copy uses British spelling ("fibres", "colour"). Latin names follow Terminologia Anatomica.
- `.impeccable/` is a local design-tool cache and is gitignored.
