# Languages

Corpus is written in English and translated through static files: nothing is generated at runtime and nothing is fetched from elsewhere. Latin names (`latin`) are never translated: they read the same in every language. The language is a preference (the cog's **Language** row, saved as `corpus:lang`), not part of the address, so a shared link opens in the reader's own language.

## Files

```
data/manifest.json            "languages": [{ id, name, ui, data?, draft? }], English first
locales/en/ui.json            every interface string, in English (the source)
locales/<lang>/ui.json        the same keys, translated
locales/<lang>/data/*.json    overlays of the content, one per data file with the same name
locales/<lang>/source.json    generated: the English each translation was made from
```

The English content stays in `data/*.json`, which remains the single source for ids, links and the data check. A language only **overlays** text on it.

- **Interface strings** (`ui.json`) are flat keys (`"panel.commonIssues": "Common issues"`) with `{name}` placeholders. A plural string is an object of the forms the language needs (`{ "one": "{n} kĺb", "few": "{n} kĺby", "other": "{n} kĺbov" }`), which is picked with `Intl.PluralRules`. Keys ending in `Html` may hold markup (`<b>`, `<span class="kbd">`); every other string is escaped.
- **Data overlays** mirror the data file, keyed by id, and hold only text:

```jsonc
// locales/sk/data/muscles.json
{ "structures": { "temporalis": { "name": "Spánkový sval", "summary": "…",
                                  "actions": ["…", "…"],                     // by index, same length
                                  "issues": [{ "name": "…", "note": "…" }],  // by index, same length
                                  "aka": ["musculus temporalis"] } },       // replaced whole (the language's own synonyms)
  "groups": { "head-muscles": { "name": "Hlava a tvár" } } }
// locales/sk/data/regions.json: { "disclaimer", "emergency", "redFlags": […], "regions": { "<id>": { "name", "causes": [{ "title", "signs" }], "redFlags": […] } } }
// locales/sk/data/links.json:   { "notes": { "<the English note>": "<its translation>" } }
// locales/sk/data/manifest.json: { "views" | "styles" | "sexes" | "layers": { "<id>": { "name", "short" } }, "linkTypes": { "<type>": { "forward", "reverse" } } }
```

Entries that share an id across sexes (the female and male breast) are keyed `breast#female` / `breast#male`. Which fields count as text is decided in one place, `TEXT_FIELDS` / `TEXT_LISTS` / `ITEM_LISTS` in `js/i18n.js`. Ids, references, `latin`, enums such as `kind` and `urgency` (their labels are in `ui.json`) and `roots` are never overlaid.

## How it works

`js/i18n.js` loads a language's files (`loadLang`) and merges them into a copy of the raw data (`forLang`, pure) **before** `js/sex.js` filters it, so `graph.js` and the panel only ever see one language. A missing string falls back to English. Each translated name keeps its English form (`nameEn`, and `en` on members), so search also finds the English name, and member links (`?m=`) stay the same in every language. `?lang=<id>` in the address picks a language (and saves it); otherwise the saved choice, then the browser's languages (finished languages only), then English.

Switching language in the cog loads the files once, rebuilds the graphs, the panel, search, Browse, the layer chips and the cog, and re-applies the `data-i18n` attributes in `index.html`. "Save for offline" also saves every language's files.

## The check

`node tools/check.mjs` (and `?debug`) checks every language against English: overlay ids and fields that English doesn't have, lists of another length, `{placeholders}` that differ, plural strings without the forms the language needs, `ui.json` keys English doesn't have, and **stale** strings whose English changed after they were translated (against `source.json`). It reports coverage (`sk: ui 265/265, data 4212/4212`). A language marked `"draft": true` may be incomplete: it isn't offered by browser detection, and missing strings aren't problems. A finished language must translate everything.

## Translating

```sh
node tools/i18n.mjs status sk          # what is translated, per file
node tools/i18n.mjs todo sk muscles    # the English still to translate, in the overlay's shape
node tools/i18n.mjs snapshot sk        # after a pass: record the English each string was made from
```

**When you change English text**, the check reports its translations as stale. Update the translation, then run `snapshot` again.

**To add a language**: add it to `manifest.languages` with `"draft": true` and a `ui` and `data` path, copy `locales/en/ui.json`, fill the overlays file by file with `todo`, run `snapshot`, and remove `draft` once the check shows 100%.

Slovak conventions: standard Slovak anatomical names in `name`, with the Latin-derived words clinicians use (`humerus`, `biceps`) in `aka` so search finds them, Slovak quotes („…“), and a non-breaking space after the one-letter prepositions (v, k, s, z, o, u, a, i). Write templates so that inserted names stay in the nominative ("← Späť: {name}"), since Slovak declension would otherwise break them.
